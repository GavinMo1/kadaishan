# 图片智能混排规则

本文是当前智能混排行为和数值的唯一详细定义。已实现；实现入口、验证结果和真机待验收见[实施说明](图片智能混排实施说明.md)，总合同见[产品需求](产品需求.md)与[产品架构](产品架构.md)。实施方案和评审过程只在Git历史查询。

## 目标与边界

面向个人相册清理：优先遇到已过几天的临时截图，连续看同一时间段的图片，同时穿插新旧片段。只使用MediaStore元数据和现有分类，不识别图片内容、不自动决定保留或删除、不建立额外浏览历史。相机拍的工作资料不能被可靠识别，这是能力边界。

## 用户看到的行为

设置提供排序选项「智能混排」，说明「近期截图更常出现，同一时间段连续看；仅图片生效，视频仍随机」。保留原四种排序。已有选择、缺省键和非法值仍按现有 Random 处理，不静默迁移；用户主动选择智能混排后生效。

例如：前几天的一小段截图 → 上周的一小段照片 → 另一段截图 → 更早的一小段图片。它是规则示例，不承诺每轮都恰好有四段或这些类型。

每次调度最多取 6 张，片段内部从早到晚；大段照片拆成多个小片段，后续片段可能隔着其他事件出现，但同一事件的各片段先后顺序不得颠倒。其他候选不足时，相邻切片可以连续播放，不保证同事件最多只连看 6 张。小段可一次看完。首版不增加“换一段”、分组删除、组级保留或新的卡面控件，避免给现有手势和撤回增加第二套语义。

轮末仍严格按用户设置的张数结束，不为凑完整片段多展示。下一轮接着既定序列走，若轮末切在片段中间，则下一轮继续剩下的部分；改排序/板块模式、退出重入或进程重建后不承诺续接。

## 算法：元数据 → 时间事件 → 小片段 → 混排序列

### 1. 输入、时间与来源

轻量 `SelectionRow(id, category, origin, dateTakenMs, dateAddedSec)`，不使用 `MediaItem` 全量装载或逐文件读取。读取 `_ID`、`DATE_TAKEN`、`DATE_ADDED` 和现有分类所需的三列字符串；分类直接复用 `classifyFields`，不另建截图识别规则。

本次 rebuild 固定注入 `nowMs`、本机 `ZoneId` 和 `Random`；扫描结束前不再次取当前时间。有效时间为大于 0 且不超过 now 的时间戳：优先 dateTaken，否则取有效 dateAdded 转毫秒，否则为未知。秒转毫秒先校验范围，避免溢出；未来时间视为无效，不让它永远占据近期池。dateAdded 可能只是导入时间，故这里只叫“时间片段”，不宣称识别了真实事件。

origin 以标准化 relativePath 为先，空时退到标准化 bucketName，再空时取该分类的统一兜底值。标准化复用/提取既有路径规则（统一斜杠、去首尾斜杠和空白、大小写不敏感），不查询来源 App。

先按当前板块与权限范围过滤，排除系统回收站及明确保留的 ID；分类、合并图片板设置与旧路径完全一致。对输入按 ID 去重，不跨图片/视频混池。

### 2. 互斥的三类候选池

年龄按 `(nowMs - effectiveTimeMs) / 24h` 的实际经过时长计算，不用自然日差。时间未知者不算近期。每张候选图片只能属于一个池，按 A → B → C 顺序归属：

| 池 | 条件 | 用意 |
|---|---|---|
| A 近期截图 | 截图，年龄 ≥3 天且 <90 天 | 提高可能已经用完的截图出场机会 |
| B 近期其他图片 | 未进 A，时间有效，年龄 <30 天，且不是年龄 <3 天的截图 | 覆盖近期相机照和保存图片，不能声称识别工作照 |
| C 其他图片 | 剩余全部，包括旧图、年龄 <3 天的截图、无有效时间的图 | 保证不被规则永久排除，给历史照片留机会 |

3 天是降低刚保存资料的推荐强度，不是禁看或自动过期；今天的截图仍可从 C 出现。老截图也不会因为超出 90 天而消失。阈值是待真机体验校准的初值，不做用户可调参数面板。

### 3. 形成近似时间事件

在每个池内，按 `(category, origin)` 分桶，再按 `(effectiveTimeMs, id)` 升序排序。有效时间条目从头向后贪心分组，满足以下全部条件才并入当前事件：同一当地自然日；与前一张时间差 ≤30 分钟；与当前事件第一张时间差 ≤3 小时。否则新开事件。

池或来源不同即不串组，避免截图夹进相机连拍；这是保守的时间邻近推断，不能保证同一事件。阈值相等时可并入，超出才拆。优先保留不同来源的清晰边界，不追求跨来源智能合并。

时间未知条目一张一个事件，不按 ID 假造时间关联。时间字段回退可以使导入图聚在一起，属于已知局限；不额外解析 EXIF 或内容纠正。

每个事件保留内部升序列表，按连续 6 张切片。事件的“下一未输出切片”是调度单位，不建立持久化 eventId，不向 UI 暴露业务承诺。

### 4. 混排调度

各池先将事件按稳定初序排列（最早有效时间、category、origin、最小 ID；未知排在最后），然后用注入的 Random 独立洗牌成事件队列。复现要求相同输入集合、now、时区及种子得到相同序列，不能依赖 Cursor 或 HashMap 的偶然遍历顺序。

使用固定循环槽位 `A → B → C → A`，每个槽位尝试从对应事件队列头输出一个切片。若事件还有后续切片，将它放回本池队尾；否则移除。池空则跳过该槽位，不重复抽取别池补这个槽；持续循环直到所有队列清空。初次从 A 槽开始。

这是 A/B/C 切片机会约为 2:1:1，不是照片张数配额，也不是任意轮数下的比例保证。6 张切片配合 A/B/C/A 的起始顺序，使三个池均非空时，默认前 20 张一定至少各看到一个切片（长度不足则更早轮到下一池）；C 不必等到第二轮。C 也含今天截图和未知时间图片，因此“出现 C”不等于必然出现旧照片；有旧图时仍是随机机会。每轮只有 1～2 张时不承诺同轮覆盖三池。某池空时自然变成其他非空池轮转；全部池空时返回空序列。队列需用 ArrayDeque/索引，不反复删除列表首项。

保证：同一快照内每个候选 ID 恰好输出一次、事件内切片先后不倒置、每个切片内部升序且连续；全部候选最终都能被遍历。不同重建间不保证未处理图片去重，不增加跨会话冷却或“很久没看过”权重。用户明确保留仍永久出池，直至其主动重置保留记录。

### 5. 伪代码

```text
snapshot = readSelectionRows(query, MATCH_EXCLUDE)  // IO，当前可见图片
rows = uniqueById(snapshot) - keptIds
lanes = partition(rows, now)
for lane in A, B, C:
    events = groupByOriginAndTime(lanes[lane], zone)
    queues[lane] = shuffle(stableOrder(events), random)
order = []
while any queue nonempty:
    for lane in [A, B, C, A]:
        if queue[lane] empty: continue
        event = queue[lane].removeFirst()
        order += event.takeNext(6)  // 严格按内部时间顺序
        if event has remainder: queue[lane].addLast(event)
return order  // 只将 ID 序列交给 BoardSession
```

## 实现与兼容

- SessionController只在图片板且选择Smart时读取SelectionRow，排除ReviewHistory明确保留项，计算完成一次安装BoardSession。视频Smart映射原Random，其他排序保留原路径。
- sort_strategy仍是图片/视频共享设置，缺省和坏值Random，用户主动选择后下一轮生效；每轮张数1～300立即生效。加载期间的最新张数在安装新会话后、ready前无挂起重放，首次构建和重试共用入口。
- 扫描在IO并通过CancellationSignal及行级检查取消，排序在Default协作取消。null Cursor、权限与读取异常显示错误和重试，不伪装空库，不静默回退随机或重置保留记录。重建单飞，不让旧结果覆盖新请求。
- 只向会话交ID序列；不改标记/撤回/保留、删除分批验活和三态回查、找回或修仙轮次奖励。外部新增媒体在下一次既有重建时进入候选。
- O(n log n)时间、O(n)轻量内存，排序完成不常驻保存元数据队列。不截断候选集换取速度，不声称常数内存或瞬时首屏。

## 验证要求

自动测试覆盖候选集合无重无漏、固定上下文可复现、时间字段和3/30/90天边界、当地自然日与DST、30分钟/3小时分组边界、来源/分类分隔、未知时间单张事件、6张切片内部与跨片顺序、A/B/C/A调度、三池非空默认前20张覆盖，以及空池/单池/双池降级。接入测试覆盖kept过滤、视频回退、取消与错误、异步轮次热更新及重试。

真机需验证近期截图、连续相机照、旧图、今天截图、大量导入及已保留项；候选不足时不承诺比例。设备性能目标：1万条构建p95≤2秒，5万条≤5秒，含查询不含图片解码，每档至少20次，另报冷/热缓存及峰值内存。主机合成算法测试不等于设备验收。权限收回、系统删除确认/取消/回查、App找回、视频保留与游戏补给另做设备回归，不由排序测试替代。

## 取舍与后续边界

该版本选择“截图优先的轻量规则”，而非语义理解：不保证识别临时相机照，不保证一个时间事件真的对应同一件事，长事件只保证切片连续和切片先后，不保证整场活动一次看完。固定 6 张只是单次调度上限，不是自动结算数，也不是可见连续观看上限。

不引入跨会话公平历史，因此反复只看开头就退出，未决图片仍可能再次出现；只有持续浏览同一快照时才保证最终遍历。若实测这一点明显影响体验，再单独讨论跨会话续看，不提前把首版做重。

当前阈值和 2:1:1 比例是可调整常量；后续若修改分池、分组或轮次语义，须同步测试与合同，不靠随机删除倾向或游戏奖励来训练算法。
