## 实现职责

以下源码入口均相对 `kadaishan/app/src/main/java/dev/sxc/kadaishan/`：

- `domain/cultivation/CultivationEngine.kt`：纯 Kotlin 确定性战斗、时间结算、掉落/保底、装备、强化、突破与转世；十分之一修为用整数保存。
- `data/CultivationRepository.kt`：独立 Preferences DataStore，JSON schema 1 校验；单写者，每块最多 1440 分钟并原子保存，继续分块直到全部时间结清，不截断超长离线收益。
- `data/CultivationRoundBridge.kt`：工具侧持久化单调轮次序号，完成事件异步送游戏，不带媒体 URI、不等待奖励；序号存储不随游戏重置清除。
- `ui/boards/PhotoCardViewModel.kt` / `VideoCardViewModel.kt`：轮次完成适配；保留与删除都构成有效决定，浏览不构成决定。游戏奖励与真实删除回查分开。
- `ui/cultivation/CultivationScreen.kt`：历练、装备、历世、换装比较和转世确认；前台按生命周期刷新；演出是简化 Canvas 山景、修士、妖兽与循环飞剑。
- `AppContainer.get`：进程内共享组装根，避免页面重建产生多个游戏写入者。

游戏文件 `cultivation`、工具侧序号文件 `cultivation_round_ids` 与 `settings`、`PendingSettlement` 分离。游戏重置只覆盖游戏存档；隐藏不暂停，显式暂停才停止收益。schema 不支持或 JSON 损坏时报告错误，不自动用新进度覆盖旧数据；完整 DataStore 文件损坏恢复仍需单独验证。

## 验证范围

统一命令见 [构建入口](../AGENTS.md#构建与安装)。当前源码与已通过门禁的产品代码一致；现存 XML 结果为 debug/release 各 134 个测试，共 268 个，失败与错误均为 0，其中修仙测试每个变体 19 个。文档同步不修改产品代码，不重复运行同一构建。

测试覆盖 15/30 天全额离线、前台/离线/分块一致性、失败仍修炼、掉落保底、时钟回拨与暂停、境界门槛、首胜幂等、装备位强化、传承保护、转世状态、十分之一修为、补给高水位去重、JSON 往返与损坏拒绝；另有每天两次操作且不穿橙装可通关的内核路径。它们不等于 Android 进程杀死、UI 连点或完整 DataStore 故障注入测试。

实际 APK 已用 `aapt dump permissions` 检查，没有 `INTERNET`；依赖合并带有 `ACCESS_NETWORK_STATE`，它不授予联网能力。尚无 OS 级网络行为验收证据。
