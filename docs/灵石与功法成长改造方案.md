# 灵石与功法成长改造方案

状态：修订/评审结论见文末；未实施。当前基线 codex/cultivation 的 25445f7。本次用户授权先出方案后继续实施，交付新版 APK 并升级应用版本。视频专题尚未实施，不纳入此次改造。

## 问题及目标

三装备位 +10 合计仅消费23100灵石；固定两功法无收集培养；战斗变快增加灵石和掉装但不增加修为。此前仿真满强化约1–1.5天，而首世通关约5天，出现长期等修为和余额积压。用户已有16万灵石，不回收、不打折、不重置。

增加“炼化灵石→修为”“挂机得功法→心得和灵石培养”“战斗胜场→击杀修为”三条连接。不做炼丹/宠物/商店/自动烧钱，不增加联网、广告、签到或后台保活。基础挂机收益继续全额无时长上限、不衰减。修仙纯Kotlin，媒体清理及补给隔离不变。沿用现有页面和Daylight，不作视觉重做。

## 规则

### 灵石炼化

当前境界 L 的每1点修为花费 `4+L` 灵石，所有世相同，不随余额涨价，无每日次数。主动选择“最多花1000”“最多花10000”“补足下层”；预览实际支出和所得，确认后原子扣石加修为。只购买整数修为，预算不足一份不扣钱；最多购买 ceil(下一层缺少的十分之一修为/10) 点，最后一份允许多出不足1点修为并完整保留，预览显示实际所得和盈余，不再继续超买，仍须主动突破，不能绕开守关。修为已足/大境界守关未过且修为已足时提示先突破或挑战；L18禁用并提示培养功法/转世。高境界价格更高，但不按下一层指数收费。16万灵石在L17最多购买7619修为（若缺口小则少买），已能明显填补等待但不会买出整套关卡。点击前后的余额、境界、修为、世ID须与确认预览一致，否则刷新预览不扣钱。暂停只停止挂机，允许手动炼化和培养。

### 六功法，一个主修位

默认御剑/长生Lv1保留，四本新增功法需挂机掉落。切换免费，先结清旧状态，不自动装备新掉落。等级 `n=1..20`，未解锁记0且不能主修。

| 功法 | Lv1作用 | 每升一级 |
|---|---|---|
| 御剑诀 SWORD | 每第三回合200%攻击 | 爆发倍率+5个百分点，Lv20为295% |
| 长生诀 LIFE | 攻击前回最大生命12% | 回复比例+1个百分点，Lv20为31%，不超满血，至少1 |
| 破军诀 ASSAULT | 首回合150%攻击 | 首击倍率+5个百分点，Lv20为245% |
| 金身诀 BODY | 敌人每次伤害减少20% | 减伤+1个百分点，Lv20为39%，伤害向下取整，非零原伤至少1 |
| 归元诀 ORIGIN | 所得基础/击杀修为乘130% | +5个百分点，Lv20为225%，炼化不受加成 |
| 聚灵诀 WEALTH | 普通战胜利灵石乘140% | +5个百分点，Lv20为235%，化解/守关奖励不受加成 |

倍数均整数计算、先乘后除，属性及资源用安全中间值，不能溢出负数。战斗轨迹记录真实增伤/回血/减伤，动画不发奖；新功法作用不能只写文案不进入引擎。守关适用战斗功法，不生成随机功法或重复刷奖励。

每次普通战胜利独立1%概率掉1份功法；连续199胜未掉则第200胜必掉。失败不推进功法保底。掉落时若有未解锁的新增功法，确定性随机在未解锁四本中选一并永久解锁Lv1；集齐后从六本中随机抽一，获得1点通用心得。集齐前不会重复，这是为了短期就能体验玩法，不假装有六本不同稀有度。与装备掉落独立，可同战同时掉；使用现有战斗sequence加独立salt，不改变装备随机序列、保底或强度。新增保底在世间保留，转世不清零。

升到第 `n` 级（2..20）消耗 `500×n²` 灵石和 `n−1` 点通用心得，确定成功无失败。提供单级与“升至可负担等级”预览，明确最大花费、最终等级、主修收益/战斗效率变化；确认原子保存。一本从Lv1到20共1434500灵石、190心得；六本共8607000灵石和1140心得，足够承接现有积蓄，不故意把16万一键清零。等级/心得上限有限是收集游戏边界，不承诺无限内容；转世及反复炼化构成长线消费。

六本已解锁状态、等级、通用心得、功法保底全部永久继承，原主修继续生效；原有转世灵石保留10%、装备强化重置、传承件等规则不变。确认页单列功法完全继承，避免误认为会清零。培养满后重复掉落继续给心得，账户不做玩法库存上限，后续内容不在此次范围。

### 修为与灵石产出

基础每分钟地图修为 `X=[2,3,5,8,12,18]` 不降低。每次普通胜利额外给该图基础一分钟修为的20%；失败只有基础。与悟性 `(10+R)/10` 和主修归元百分数P（未主修=100）相乘。基础和击杀各持久化独立模500余量 `baseRemainder`、`killRemainder` (0..499)：

`基础numerator = X × (10+R) × 5×分钟 × P + oldBaseRemainder`

`击杀numerator = X × (10+R) × 胜场 × P + oldKillRemainder`

分别除500，商为各自本批十分之一修为、余数各自保存，总修为为两项商的安全求和。BigInteger做中间计算，Long仅最终资源饱和。报告基础与击杀按同源商累加，总报告修为为历史/基础/击杀的饱和和；不在Long极限用普通加法校验，不把机器饱和当正常离线封顶。清报告保留全部数值余量，转世清零当世修为和两项修为余量。旧报告标“旧规则修为”而不是伪拆历史。小时预测基于理想3600000ms工作量：显示预计基础与击杀合计，注明配置预测，实际受战斗余量影响。
聚灵普通胜利灵石同理保存 `stoneRemainder` (0..99)，`(胜场×地图胜利灵石×聚灵百分数 + 旧余数)/100`，转世清零该小数（确认页注明不足1灵石不继承）；非聚灵P=100。两项修为余数随当世修为一起转世清零，功法切换不丢余数。炼化修为及手动花费不进入挂机入账报告，操作回执单列，不能重复领取。补给30分钟使用相同规则，真实时间与补给仍分列。普通失败不刷功法、不增加击杀修为。

升级、换功法、突破、换装先结清，再通过现有 transition 按周期比例映射战斗余量。离线期间功法仅解锁/心得增长，不自动主修/升级，因此批内战斗快照固定，可保持一次画像和事件序列循环，不增加逐分钟主线程逻辑。

## 存档、升级与失败

应用versionCode 1→2，versionName 0.1.0→0.2.0；包名和debug签名不变，保留原签名证书并核对APK签名摘要以支持覆盖。APK产物复制为带版本名的文件，aapt核验实际版本和无INTERNET。往后每次对外交付APK递增versionCode并更新versionName，规则写入AGENTS，不给历史构建伪造版本。

游戏schema2→3，新增功法等级表、心得、功法保底、三项分数余量、报告基础/击杀/历史修为和功法掉落/新解锁列表（最多六种的集合，不保存无限逐件日志）。DataStore文件和state_v1键不变。schema1/2保留原模拟器，所有新规则仅version>=3生效；旧版等级1战斗行为保持原样。

迁移先写私有校验备份（schema1沿用原文件、schema2单独cultivation-v2-backup.json，不覆盖v1备份），失败不迁移不重置。按旧schema结清完整离线分钟，沿用每批≤1440分钟可恢复落盘机制、无总时长上限；再原子安装schema3：原石/修为/强化/装备/主修/时间/seed/sequence/保底/补给代次完整保留，御剑长生初始化Lv1，新增功法未解锁，新余量/功法保底0，历史报告修为归入历史分项。schema1先走现有1→2步骤再2→3，备份校验允许对应旧schema，不混文件。零分钟、暂停、时间回拨也要可升级。拒绝未来版本与缺失必填新字段，不用默认新档覆盖。

旧不足一分钟按原时钟余量保留，升级后的完整分钟起使用新规则；旧半场战斗余量保留（初始功法Lv1未改变周期）。在schema2已提交但schema3提交前杀进程，下次读取schema2继续，不重新发旧时间；提交已完成但ACK丢失仍强制cache失效重读，不重复收入。迁移不重置奖励outbox/receipt/generation；新老补给处理继续遵守协调锁和游戏mutex，不新增锁次序。

手动炼化/培养都复用repo.update串行事务与落盘后回执；预览包含world、level、xp、stone、功法/心得等消费相关快照，期间若有收益到达，提示刷新预览，不能按旧报价扣新余额。错误/取消原状态保留，重试不重复扣款。明确重置才清空功法和资产。降低应用版本不受支持，旧APK无法理解schema3，保留可人工恢复的升级备份，不自动回滚丢新进度。
