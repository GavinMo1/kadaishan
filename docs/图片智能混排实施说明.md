# 图片智能混排实施说明

实现状态：已实施，待真机验收。需求和数值规则见[方案](图片智能混排方案.md)；产品总合同见[需求](产品需求.md)与[架构](产品架构.md)。

## 使用

安装最新 debug APK 后，在设置 → 排序选择「智能混排」。沿用既有排序/缺省随机，不自动改用户设置；选中后下一轮生效。图片统一板与分板均支持，视频仍随机。相机工作照不做内容识别；仅按来源与时间粗分组，不会自动标记删除。

## 实现落点

以下代码相对 `kadaishan/app/src/main/java/dev/sxc/kadaishan/`：

- `domain/selection/SmartOrder.kt`：轻量行模型与纯算法，时间校验、三池、近似事件、切片调度、稳定去重；支持注入时钟上下文、时区、随机源和取消检查。不读取图片、不保存浏览历史。
- `data/MediaStoreDataSource.kt`：一次图片集合查询七列元数据，沿用权限/回收站查询及分类过滤；扫描支持平台 CancellationSignal 与行级取消；null Cursor 按读取失败处理。
- `domain/session/SessionController.kt`：图片 Smart 走后台计算，视频 Smart 走旧 Random；排除明确保留；成功后一次安装 ID 序列。BoardSession 内核未改。
- `data/SettingsRepository.kt` / `ui/settings/SettingsScreen.kt`：SMART 编码、可选入口及图片/视频差异说明；原值及随机回退兼容。
- `ui/boards/PhotoCardViewModel.kt` / `PhotoCardScreen.kt`：构建失败、权限失效、重试与单飞门禁；新会话提交时重放最新每轮张数，防止异步构建覆盖热更新。权限错误提供重新授权及重试。

主线程保留会话动作，扫描 IO、排序 Default；排序结束不保存元数据队列。保留/撤回仍先完成原 DataStore 写入，未结算删除、回查、恢复和修仙奖励语义不变。无新增依赖、权限、数据库、识别模型或后台服务。

## 已完成验证

统一 `assembleDebug test --console=plain --no-daemon` 门禁通过，debug/release 各 155 个测试，共 310 个，失败与错误均为 0。新增 21 个测试每变体，覆盖时间/分组/调度边界、确定性去重、三池首轮出场、取消、保留过滤、视频降级、设置与板块兼容，以及真实图片 VM 的异步轮数热更新、加载错误、重试、销毁与保留撤回。

主机 JVM 上 5 万条未知时间元数据的排序/集合校验约百毫秒量级；这只是合成数据单次路径，不含 MediaStore 查询或图片解码，不作为真机 p95/峰值内存验收。原方案阶段独立小脚本验证也不代替产品测试。

APK 已以 aapt 检查权限，没有 INTERNET；仍含既有 ACCESS_NETWORK_STATE（不授予联网能力）。没有连接设备，未安装到手机，也未验证原生页面截图、真实权限撤销和删除/找回链路；不声称这些已经通过。

## 待真机验收

1. 选择智能混排，确认下一轮生效；体验近期截图、同日连续照片、旧照片、今天截图和大量导入图。确认保留项仍出池、撤回仍准确、下一轮接着既定序列。
2. 加载期间改每轮张数；读失败重试；收回权限后重新授权；后台/前台及页面退出后无旧加载结果覆盖。
3. 按方案采样 1 万/5 万条元数据构建耗时、冷/热差异及峰值内存，核对设备 p95 目标。阈值效果由真实相册反馈校准。
4. 删除系统确认/取消/回查、App 内找回、视频保留与修仙轮次奖励冒烟；网络行为需单独 OS 级证据。
